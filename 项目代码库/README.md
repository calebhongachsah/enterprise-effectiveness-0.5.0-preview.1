# 企业效能运营平台 · 统一代码库

本目录是产品从 Demo 到正式版本持续演进的唯一代码位置，版本通过 Git commit/tag 管理，不复制代码目录。

V0.1 是本机 Web Demo：上传 UTF-8 CSV、配置字段与环节、计算效率/效果指标，并通过团队矩阵及原因与改善分析完成从观测到验证的运营闭环。运行环境 Node.js 24 或以上。

V0.5 为单流程自托管预览。安装时创建的首个管理员可独自完成数据接入、配置和日常运营，无需创建额外角色。

在本目录首次运行：

```sh
npm install
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。生产式本地运行：

```sh
npm run build
npm start
```

Docker Compose 同时管理正式存储和应用。初始化令牌、HTTPS 和升级配置见[部署与运维指南](infra/README.md)。

检查命令：

```sh
npm test
npm run validate
npm run demo
```

- `apps/web`：React 数据配置、团队看板、导入批次、原因与改善分析界面。
- `apps/api`：本地 HTTP API，以及 SQLite 演示/PostgreSQL 正式存储的二选一实现。
- `packages/core/v01.ts`：CSV、数据质量、阶段计算和指标汇总。
- `packages/contracts/v01.ts`：前后端共享契约。
- `data/software-development-demo-utf8.csv`：可直接上传的演示数据。
- `packages/core/index.mjs` 及既有模板：启动验证资产，迁移期间继续保留。
- `templates/service-request.json`：通用服务请求的模拟流程与 SLA 示例。
- `templates/software.json`：研发流程示例；阈值仅用于演示。
- `examples`：人工可复算的三个阶段实例，均为模拟数据。
- `scripts`：模板检查和两个场景的命令行演示。
- `tests`：最小领域规则测试。
- `infra`：V0.2 PostgreSQL 表结构、索引、Docker 基线及备份恢复说明。

两个示例的完成样本都为 4h、10h，在途为 12h。完成均值为 7h，P90 为 10h，完成超期率为 50%，在途超期数为 1。服务请求受理阶段 P0 阈值为 4h，研发开发阶段 P0 阈值为 8h，因此均值红绿不同。

## V0.1 边界

- 平台按 CSV 提供的权威字段计算，不推断返工或修改客户流程。
- V0.1 手工上传数据，不自动刷新。
- 角色切换仅用于演示，不是生产权限系统。
- SQLite 文件保存在本机 `data/demo.sqlite`，不进入 Git。
- 原因和根因结论由人填写，系统不自动确认因果关系。

## 已发布能力（V0.1—V0.3）

- CSV 先形成待发布批次，发布前不改变正式看板。
- 导入按单据编号识别新增、更新和无变化，并绑定当时的配置版本。
- 流程配置支持草稿与发布，既有历史观测不会被新 SLA 改写。
- 已完成 PostgreSQL 全量业务存储、启动前迁移、真实数据库测试和 SQLite/PostgreSQL 启动时二选一。
- 已完成本地账号、五类角色、团队数据权限、账号生命周期及管理员审计日志页面。
- 已完成带 SHA-256 清单和保留策略的 PostgreSQL 备份，以及维护状态恢复和恢复后完整性检查。
- 已完成 PostgreSQL 客户数据源连接、一次配置、全量/增量同步、定时任务、错误重试和结构变化保护。

## 开发约束

业务名称与阈值写入模板；核心不得新增 `if security` 一类业务分支。指标改变先更新口径和样本，再改计算。所有项目文件、生成物和临时文件均留在本项目根目录内。
